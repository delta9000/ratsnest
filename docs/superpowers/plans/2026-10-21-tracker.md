# Tracker Implementation Plan

> Steps use checkbox (`- [ ]`) syntax for tracking. A task is done only when
> its named tests pass.

**Goal:** a first-party `tracker` module that plays a plain-text `.trk`
pattern file, per `docs/superpowers/specs/2026-10-21-tracker-design.md`, and
a port of `patches/mainstage.patch` that uses it.

**Architecture:** `src/io/trk.{h,cpp}` parses and flattens a `.trk` text into
a `TrkSong` (resolved per-row, per-track states plus order-step offsets).
`src/graph/trackfiles.cpp` is a non-RT build pass (after subpatch expansion)
that reads each tracker's `file:`, reports `.trk` diagnostics with
file:line:col, embeds the text as config `text`, and returns the path for the
watcher. `src/dsp/modules/tracker.cpp` parses `text` in `init()` and only
indexes arrays in `process()`.

**Tech stack:** C++20, doctest. No new dependencies.

## Global constraints

- Rule 3: nothing reachable from `process()` / `copy_state_from()` allocates.
- Rule 6: every `.trk` error is `file:line:col`; the last good graph plays.
- Complexity: no hotspots (cyclomatic ≤ 15, bodies ≤ 80 lines). Report the
  score; do not raise `docs/complexity.json` without the owner.
- Do not edit the envelope, fm, filter, lpg/sampler/switch or dynamics module
  files (parallel work).
